本包由 TextDeck 仓库（<https://github.com/ookoukibob/TextDeck>）的 `main` 分支
源码整理、实际编译并验证后打包而成。

- 整理与构建日期：2026-10-29
- 构建环境：Windows 11 x64（10.0.26300），Visual Studio 2022 Build Tools（MSVC 14.44.35207），Windows SDK 10.0.26100
- 文档中的快捷键、目录名、命令行参数均取自本包内实际源码与程序输出

> **第一次使用？** 请先看 **《功能说明.md》**（软件能做什么、使用限制）和
> **《安装说明.md》**（包内文件说明、安装与首次使用步骤）。本文件是详细操作手册，
> 末尾附录为构建与变更记录（普通用户可忽略）。

## 1. 这是什么

TextDeck 用来**把你事先准备好的文字，逐字符输入到当前获得焦点的窗口**里。
它不是复制粘贴，正文不经过剪贴板，而是逐个字符模拟键盘输入。

本包含三个功能部分，彼此独立，可以只用其中一个：

| 部分 | 作用 | 需要驱动/管理员吗 |
|---|---|---|
| **TextDeck 主程序**（`02-TextDeck-Main`） | 图形界面程序，保存一段文字，按快捷键让它输入到目标窗口 | 软件输入模式：都不需要 |
| **TextDeck Mapping**（`01-TextDeck-Mapping`） | 命令行工具，把键盘、鼠标、游戏手柄、串口、UDP 等输入事件映射成按键或按键脚本 | 输出到键盘时才需要驱动 |
| **ESP32-S3 固件**（`03-ESP32-Firmware`） | 烧录到 ESP32-S3 开发板上，让开发板变成一只真正的 USB 键盘，由主程序通过串口指挥它打字 | 不需要驱动、不需要管理员 |

主程序有三种输入模式，**必须在界面上明确选择，程序不会自动切换**：

1. **软件输入模式（SendInput，无需驱动）** —— 最省事，推荐先用这个。支持中文和 emoji。
2. **ESP32 USB HID 模式** —— 需要一块烧好固件的 ESP32-S3 开发板。
3. **TextDeck HID 模式（需已装驱动）** —— 需要内核驱动，而驱动目前没有生产签名，见第 6 节。

## 3. 主程序安装与使用（推荐：软件输入模式）

TextDeck 主程序**免安装**：不需要 Installer，不写注册表，不装服务。

### 3.1 启动

1. 进入 `02-TextDeck-Main` 文件夹。
2. 双击 `VirtualHIDTyper.exe`。
3. 如果 Windows 弹出 SmartScreen 提示（"Windows 已保护你的电脑"），这是因为本程序的
   可执行文件没有商业代码签名证书。选择"更多信息"→"仍要运行"即可。
4. 程序以**普通用户权限**运行即可（程序清单要求的是 `asInvoker`，不会请求管理员）。

界面出现后，先点选单选按钮 **「软件输入模式（SendInput，无需驱动）」**。

### 3.2 输入一段文字

1. 在多行文本框里输入或粘贴要发送的文字。英文、数字、标点、中文、emoji 都可以。
2. 设置"间隔(ms)"：每个字符之间的等待时间，默认 30，可调范围 5–2000。太小的间隔在
   性能较差的机器上可能让目标程序漏字。
3. 点 **保存文本**（或直接点"开始"）。文本和设置会自动保存到
   `%APPDATA%\VirtualHIDTyper\`（`text.txt` 与 `settings.ini`），下次启动自动载入。
4. 关闭主窗口不会退出程序——它会缩到系统托盘继续待命。

### 3.3 触发输入

1. 点"开始"后会有 **3 秒倒计时**，请在倒计时内把光标点进目标窗口的输入框。
2. 或者：先把焦点切到目标窗口，然后按**开始快捷键**。
3. **默认快捷键**（三个互相独立，可分别改）：
   - 开始输入：`Ctrl+Alt+Shift+F9`
   - 紧急停止：`Ctrl+Alt+Shift+F10`
   - **专用停止键**：`Pause`（**不带任何修饰键的单键**）
4. **推荐优先用「专用停止键」停止**。按住 Ctrl/Alt/Shift 期间到达的 HID 字符会被目标窗口
   当成快捷键吞掉；单键停止不按任何修饰键，从原理上避开这个窗口，而且 `RegisterHotKey`
   会消费该键，它不会落到目标窗口里变成文字。组合键 `Ctrl+Alt+Shift+F10` 继续保留作备用。
5. 三个键都可以在「快捷键设置」里重按一遍改掉（点输入框后直接按新键），
   三者不能相同；`Pause` 可换成任意单键（如 `F10`、`ScrollLock`、`End`）。
   「恢复默认」一键还原为上面三个默认值。
   配置存在 `%APPDATA%\VirtualHIDTyper\settings.ini` 的 `HotkeyStart` / `HotkeyStop` / `HotkeyStop2`。
6. 如果某个组合被别的软件占用，程序注册会失败并在状态栏显示「注册失败」（含 Windows 错误码），
   **其余两个键不受影响**；**实际生效的按键以程序界面上显示的为准**。
   遇到这种情况，请关闭占用的软件，或换个按键。
7. 输入结束（或按停止键）后，状态栏会给出统计："本次实际输入 X 字符，跳过 Y 字符"。

> **笔记本提示**：多数笔记本没有独立的 `Pause` 键。请在「快捷键设置」把专用停止键改成
> 一个方便按的单键（例如 `F10` 或 `ScrollLock`），不要为此去按 Ctrl/Alt/Shift 组合。

### 3.4 软件输入模式能做什么、不能做什么

- **支持任意 Unicode 文本**，包括中文、日文、emoji、特殊符号。
- 它是 **Windows 用户态的 `SendInput` 键盘事件**，机制上等于"有一个很快的打字员在按键"。
  **它不是 USB HID 设备**，也不会在设备管理器里出现任何新硬件。
- 它**无法**向以管理员权限运行的高完整性窗口输入文字（Windows 的 UIPI 限制）。
  这类情况下程序会直接报错并停止，**不会尝试绕过**系统安全机制。
- 输入过程中若前台窗口发生变化，程序会自动停止并释放按键，防止文字串到别的窗口。
  这个"检查焦点→发送"不是原子操作，切换瞬间极少数字符可能丢失，属于已知局限；
  输入期间请勿切换窗口。

## 4. ESP32-S3 固件烧录与使用

这一节是把开发板变成"真 USB 键盘"的完整流程。如果你只想在电脑上打字，
可以跳过本节，直接用第 3 节的软件输入模式。

### 4.1 需要准备什么

- 一块 **ESP32-S3** 开发板，建议 16 MB Flash + 8 MB PSRAM 的 N16R8 类板卡
  （这是本项目配置所对应的规格）。
- 一根**能传数据**的 USB 线（很多线只能充电）。
- Arduino IDE 2.x（内含 arduino-cli），并在开发板管理器中安装 **esp32 by Espressif**
  核心（3.x 系列）。
- 电脑上不需要装任何驱动：烧录用开发板的 USB 口，Windows 自带串口驱动即可。

### 4.2 在 Arduino IDE 2 中打开并设置

1. 打开 Arduino IDE 2 → `文件` → `打开` → 选择本包的
   `03-ESP32-Firmware/firmware/esp32_hid_text_device` 文件夹里的
   `esp32_hid_text_device.ino`。
2. 开发板选择 **ESP32S3 Dev Module**。
3. 打开 `工具` 菜单，逐项设置（**这几项必须对上，否则编出来的是另一个设备**）：

   | 菜单项 | 必须设置为 |
   |---|---|
   | Flash Size | **16MB** |
   | PSRAM | **OPI PSRAM** |
   | USB Mode | **USB-OTG (TinyUSB)** |
   | USB CDC On Boot | **Disabled** |

   为什么必须这样：
   - `USB Mode = USB-OTG (TinyUSB)` 是"HID 键盘 + 串口"复合设备的必要条件；
   - `USB CDC On Boot = Disabled` 是**故意的**：固件自己接管了串口通道，
     不让核心再抢一个 USB 串口，否则两条通道会混在一起。

   对应的命令行 FQBN 就是：
   ```
   esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,USBMode=default,CDCOnBoot=default
   ```

4. 选择正确的端口，点"验证"（编译）→"上传"（烧录）。

### 4.3 关于烧录的三个重要提醒

- **不要**使用"全片擦除"（Erase All Flash / `EraseFlash=all`）来解决一般的烧录失败。
  普通上传只会替换程序固件，板子里已保存的文字会保留；全片擦除会把这些内容一起清掉。
- **不要**修改分区表，**不要**动 eFuse。
- 烧录失败时按顺序检查：串口是否被别的程序占着（比如桌面写入工具还开着）、
  开发板型号是否正确、端口是否选错。改完这些再重试。

### 4.4 连接与使用

1. 用 USB 线把开发板的**原生 USB 口**（GPIO19 = D-，GPIO20 = D+）接到电脑。
   日常使用只需要这一根线。
2. Windows 会同时认出两个设备，都用系统自带驱动，不需要额外安装：
   - **HID Keyboard Device**（用来真正打字）
   - **USB 串行设备 (COMx)**（用来下发文字和控制命令）
3. 运行 `02-TextDeck-Main/VirtualHIDTyper.exe`，选择 **「ESP32 USB HID 模式（原生 USB 单线，无需驱动）」**。
4. 在串口下拉框里选择刚才那个 COMx。程序通常会自动选中 Espressif 的接口，
   如果选错可以手动改，选择会被记住。
5. 编辑并保存文字 → 切到目标窗口 → 按开始快捷键 `Ctrl+Alt+Shift+F9`；
   停止用 `Ctrl+Alt+Shift+F10`、托盘菜单"停止输入"或窗口上的"停止"按钮。
6. 可选：板上的 **BOOT 键**（GPIO0）也可以本地触发一次输入，按一下即松开。
   输入过程中按 BOOT 不会打断当前这一轮。

### 4.5 字符限制（务必先看）

ESP32 固件走的是**真实 USB HID 键盘**，它发出去的是"按键位置"，不是字符编码。
因此：

- **支持**：US 键盘布局下可表达的 ASCII 可打印字符（`0x20`–`0x7E`，即英文、数字、
  常见英文标点、空格），以及换行 `\n` 和制表符 `\t`。
- **不支持**：**中文、emoji、其它任意 Unicode 字符、回车符 `\r`**。
  这些内容在写入设备前就会被拒绝并明确提示，不会静默替换，也不会偷偷改走剪贴板。
- **长度上限 10,240 字节（10 KiB）**，按字节计算（ASCII 每字符 1 字节）。
  超长或空文本两端都会拒绝，不做静默截断。
- **换行归一化**：`\r\n` 一律折算成单个 `\n`（孤立的 `\r` 也折算成 `\n`），
  所以含 CRLF 的文本落盘后再读回，长度会少掉 CR 的个数——这是设计行为，不是丢字。

#### 4.5.1 CapsLock 会翻转所有字母（重要）

ESP32 发出的是**真实 USB 键盘按键**，和人手打字完全一样，因此**受 CapsLock 状态影响**：

| CapsLock | 设备打出 `ABC` | 设备打出 `abc` |
|---|---|---|
| 关 | `ABC` | `abc` |
| **开** | **`abc`** | **`ABC`** |

也就是说 **CapsLock 打开时，所有字母的大小写都会反过来**，标点与数字不受影响。

- 程序**不会**擅自修改系统的 CapsLock 状态；
- 用 ESP32 模式输入字母前，请确认 CapsLock 处于你想要的状态；
- 状态栏与快捷键设置不会显示 CapsLock，请自行用键盘上的指示灯或系统状态确认。

#### 4.5.2 中文输入法也会改写按键

同理，如果当前窗口挂的是**中文输入法（如微软拼音）**，ESP32 打出的字母会进入输入法的
候选/组字状态，空格会被当成"上屏"消耗掉，标点会被转成全角（`!`→`！`）。

- 用 ESP32 模式前，请把输入法切到**英文/纯字母模式**；
- 软件输入模式（SendInput）走 Unicode，不受输入法影响，中文可以正常输入。

**所以：要输入中文，请用软件输入模式（SendInput），不要用 ESP32 模式。**

### 4.6 可选的独立写入工具 `hid_text_writer.py`

`03-ESP32-Firmware/tools/esp32-desktop/hid_text_writer.py` 是一个独立的小工具，
不依赖主程序，可以单独把文字写进开发板或读回来核对。需要 Python 3 和 pyserial：

```powershell
cd 03-ESP32-Firmware\tools\esp32-desktop
python -m pip install -r requirements.txt
python .\hid_text_writer.py                      # 打开图形界面
python .\hid_text_writer.py --port COM4 --ping    # 查询设备（查固件版本/状态）
python .\hid_text_writer.py --port COM4 --write "要写入的文本"
python .\hid_text_writer.py --port COM4 --read     # 读回校验
```

把 `COM4` 换成你实际看到的串口。它的字符与长度限制和 4.5 节完全一致。

## 5. TextDeck Mapping 工具包使用

Mapping 是一个**命令行**工具（没有图形界面），把各种输入信号变成按键动作。

### 5.1 基本用法

打开命令提示符（Win+R 输入 `cmd`），进入 `01-TextDeck-Mapping` 目录：

```bat
cd /d <解压路径>\TextDeck-Portable\01-TextDeck-Mapping

map_app.exe example > my.json      生成一份可用的示例配置
map_app.exe validate my.json       校验配置（出错会指出是哪个字段）
map_app.exe devices                列出当前真实存在的输入设备
```

`devices` 会列出键盘、鼠标、手柄等设备路径，可以据此填写配置里的 `source`。

### 5.2 先做安全测试：record 模式

**第一次运行务必用 `record` 输出模式**——它只把"本该按下的键"记录/打印出来，
**不会真的按任何键**，因此不会打扰你正在用的电脑：

```bat
map_app.exe run my.json --output record --seconds 30
```

`--seconds 30` 表示 30 秒后自动停止；写 `--seconds 0` 则一直运行到按回车。

确认行为符合预期后，再换成真正输出的模式：

```bat
map_app.exe run my.json --output sendinput
```

`--output` 可取值：

| 值 | 含义 | 前提 |
|---|---|---|
| `record` | 不输出，只记录（默认） | 无 |
| `sendinput` | 发送普通键盘事件 | 无 |
| `hid` | 通过 TextDeck 虚拟 HID 驱动输出 | **必须已安装并可使用内核驱动**（见第 6 节） |

还可以加 `--udp <端口>` 让它接收 UDP JSON 事件。

### 5.3 配置与脚本

配置是 JSON（version 1）。本包已带一份生成的 `example.json`，可以直接改。
格式、所有可用的触发器（`press`/`momentary`/`long_press`/`double_tap`/`combo`/
`sequence`/`cooldown` 等）和动作（`key_down`/`key_tap`/`key_combo`/`type_text`/
`delay`/`repeat`/`conditional`/`profile_switch`/`cancel_sequence` 等）在
`01-TextDeck-Mapping/README.md` 里有完整清单；
键名（`a`–`z`、`0`–`9`、`f1`–`f24`、`ctrl`/`shift`/`alt`/`gui`、`enter`/`esc`/`tab`/
`space`、方向键、US 标点）在加载时会被校验，写错会直接报错并指明字段。

注意：HID 输出后端下的 `type_text` 同样只支持 US-ASCII 可打印字符加 `\n`/`\t`，
遇到不支持的字符会**明确报错**而不是静默丢弃。

### 5.4 设备与依赖说明

- 物理键盘/鼠标的事件通过 Windows Raw Input 读取，**不需要**驱动。
- 游戏手柄通过 XInput 读取，需要手柄已连接到电脑。
- 串口输入源需要你有对应的串口设备。
- **只有 `hid` 输出模式需要 TextDeck 的内核驱动**；没有驱动时请用 `sendinput` 或 `record`。
- Mapping 会按设备标识过滤掉 TextDeck 自己的虚拟 HID 输出设备，
  避免"自己触发自己"的回路。

## 6. 驱动与系统安全边界（重要）

TextDeck 的 `TextDeckHid 模式`（虚拟 HID）依赖一个内核驱动。关于它的**真实状态**：

- 驱动的源代码是这个项目原创的，可以自行编译；
- 但**没有生产签名的发布版本**。仓库文档 `docs/SIGNING.md` 明确记录：生产签名需要
  EV 证书与微软认证签名，目前是**阻塞**状态；当前使用的 VID/PID 也仅用于测试。
- 因此：**本分发包不包含任何驱动二进制文件（`.sys`/`.cat`/`.inf`）**。
  没有把未签名驱动打包成"可直接安装的正式驱动"，也不声称它开箱即用。
- 想使用 `TextDeck HID 模式` 或 Mapping 的 `hid` 输出，需要你**自行解决驱动编译、
  测试签名与部署**的问题，并且要符合你自己系统的签名策略。这是发布包之外的独立工作。

本包**没有**、也不会：

- 启用 Windows 测试模式（TESTSIGNING）；
- 关闭 Secure Boot；
- 导入任何测试证书；
- 修改任何 Windows 启动安全设置。

以上都属于需要你自行判断的显式操作，程序不会替你打开。

### 6.1 本包现在包含驱动源码

`04-Driver-Source/` 提供驱动与其工具的完整源码，因此「TextDeck HID 模式」
不再是"看得见却无从下手"的选项：

```powershell
cd 04-Driver-Source\windows\driver-tools
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_driver.ps1   # 需要 VS2022 Build Tools + WDK
```

产物是**未签名**的 `.sys`/`.inf`。要让 Windows 加载它，必须自行完成测试签名
或正式签名（见 `04-Driver-Source/docs/SIGNING.md`）。本包**不包含**任何
证书、私钥或已签名驱动，也不会替你打开 TESTSIGNING 或关闭 Secure Boot。

没有驱动的正常状态：`TextDeck HID 模式`启动时会提示设备打不开（错误码 5，
即"拒绝访问"，因为设备 ACL 只授权 SYSTEM 与 Administrators）。
此时程序会弹出三选一对话框：**是** = 改用软件输入模式继续；**否** = 留在原模式；
**取消** = 停止，不发送任何字符。

## 7. 常见问题

**Q1：双击 `VirtualHIDTyper.exe` 没反应 / 一闪就没了**
先确认解压完整（不要直接在压缩包里双击运行）。再试：按住 Shift 右键文件夹 →
"在此处打开 PowerShell 窗口"，输入 `.\VirtualHIDTyper.exe` 看是否有报错信息。
若被 SmartScreen 拦截，按 3.1 第 3 步处理。程序是 x64 的，32 位 Windows 无法运行。

**Q2：按了开始快捷键，但没有文字出来**
按顺序检查：① 模式是否选的是"软件输入模式"或"ESP32 USB HID"；② 焦点是否在目标
窗口的输入框里（程序拒绝向自己的窗口输入）；③ 目标窗口是否以管理员权限运行
（高完整性窗口收不到 SendInput，会报错误码 5）；④ 状态栏的统计数字是多少
（"实际输入 0 字符"通常意味着焦点不对）。

**Q3：找不到 COM 端口 / 端口被占用**
先看设备管理器里"端口(COM 和 LPT)"下有没有新增的 USB 串行设备。没有的话：
换一根**能传数据**的 USB 线、确认插的是开发板的**原生 USB 口**而不是调试口。
提示"拒绝访问/被占用"通常是另一个程序（串口助手、`hid_text_writer.py`、另一个
VirtualHIDTyper 实例）还开着同一个端口，关掉它再试。

**Q4：ESP32 固件配置不对（编出来不工作）**
回到 4.2 的四个菜单项逐项核对。最常见的三种错：Flash Size 用的是 4MB、
PSRAM 没开/选成 QSPI、USB CDC On Boot 选成了 Enabled。
USB CDC On Boot 选错时，设备可能只出现串口不出现 HID 键盘，或反之。

**Q5：输入到一半，文字跑到了别的窗口**
程序在每次发送前都会检查前台窗口，一旦变化就立即停止并释放按键。
但"检查"和"发送"不是一个原子操作，极短的时间窗内仍可能有字符落到新窗口。
建议：输入过程中不要切换窗口；需要中断时立刻按 `Ctrl+Alt+Shift+F10`。

**Q6：某些字符没被输入（被"跳过"）**
- 软件输入模式：几乎不会有，除非是孤立代理项或 NUL 这类无法作为键盘事件发送的内容。
- ESP32 模式 / TextDeck HID 模式：中文、emoji、非 US 布局字符都会被跳过并计数。
  需要中文请改用软件输入模式。
- TextDeck HID 模式额外受目标机键盘布局影响：HID 只发"按键位置"，如果目标系统的
  活动布局不是美式键盘，Shift 标点可能变成别的字符。

**Q7：Mapping 配置校验失败**
`map_app.exe validate` 的报错会直接给出出错位置（例如
`profiles.default[0].trigger: unknown trigger 'nope'`）和原因。
按提示改 JSON 即可：触发器名、动作名、键名都必须来自 `01-TextDeck-Mapping/README.md`
列出的集合；JSON 语法错误会报"第几行第几列"。

**Q7.5：校验清单时提示某个中文文件"缺失"**
用记事本打开 `SHA256SUMS.txt` 能看到 `使用说明.md` 那一行，但 PowerShell 的
`Get-Content` 报找不到文件——这是 PowerShell 5.1 默认按 ANSI 读取 UTF-8 造成的
假象。请改用包内 `verify-package.ps1`，或显式指定编码：
`Get-Content SHA256SUMS.txt -Encoding UTF8`。

**Q8：提示虚拟 HID 驱动不可用**
这是预期情况——本包不含驱动，见第 6 节。改用软件输入模式（主程序）或
`--output sendinput`（Mapping）即可完成同样的工作。

## 附录 C：候选包 2 —— ESP32 USB HID 模式的停止修复

构建基线：仓库提交 `06a0346` 加本仓库修复补丁。相对候选包 1 的变化：

| 变更 | 说明 |
|---|---|
| ESP32 模式停止失效 | 用「开始输入」按钮启动时（3 秒倒计时），倒计时标志在真正开始输入后没有被清除，于是之后每一次停止都被当成"取消倒计时"：界面显示「已取消（未发送任何按键）」，设备却继续把整段文本打完。现在该标志在"倒计时结束、真实输入开始"这一节点清除，停止请求一律交给工作线程向设备发送 CANCEL。 |
| 停止与任务的优先级 | 只要还有任务在跑，停止请求就绝不再走"取消倒计时"分支；重复按停止只是重复置位事件，不会打断正在发送的 CANCEL，也不会死锁。 |
| 状态一致性 | 任务未结束时不再把状态置回 IDLE；重复按停止不会把「已停止」覆盖成「当前没有进行中的输入任务」；实际输入字符数以设备 CANCEL 后的最终计数为准（设备计数器可能滞后 1 个字符，不会多报）。 |
| 新增测试脚本 | `02-TextDeck-Main/source/windows/VirtualHIDTyper/esp_stop_regress.ps1`，覆盖 11 类停止场景，在真实开发板上运行，按目标窗口实际收到的文本判定。 |
